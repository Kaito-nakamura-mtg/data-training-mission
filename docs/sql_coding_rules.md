# SQLコーディングルール集

SQLを書く際は、以下のルールに従ってください。🔴 Must は必ず守るルール、🟡 Want は推奨されるルールです。

## 🔴 Must（絶対守るべき必須ルール）

### 1. 基本フォーマット・インデント

- 大文字小文字：すべて小文字を使用する
- 文字コード：UTF-8で記述する
- 統一感：記述方法はSQLファイル内で統一する
- インデント幅：空白4文字を使用する
- 改行・スペースのルール：
  - カンマ（`,`）と演算子は、改行後「次の行の先頭」に置く
  - カンマの後、および演算子の前後には半角スペースを入れる
  - 各句のキーワード（`select`、`from`、`where` 等）自体はインデントせず、その後の要素をインデントする
  - 各句のキーワードの後は必ず改行する（※ただし `select` の後に1カラムだけ指定する場合は改行不要）
  - `case` 式で `when` が2つ以上ある場合は改行する
  - JOINのフォーマット：`join` 句は `from` よりも一段深くインデントする

### 2. コメントの記述

- コメントアウト：`--` は使用せず、必ず `/* */` を使用する
- コメントの記載必須箇所：
  - WITH句：何のデータの塊か、主キー（PK）、処理の目的を記載する
  - WHERE句：各条件が何のために絞り込みをしているのかを記載する
  - ハードコード：コード値（フラグの数字など）をそのまま使う場合は、論理名をコメントで添える

### 3. 命名規則・エイリアス

- エイリアスの明記：カラム名・テーブル名にエイリアス（別名）をつける際は、必ず `as` を明記する
- 命名の具体性：サブクエリ名やテーブルのエイリアスは、内容が直感的にわかる名前にする
- 予約語の禁止：カラム名にSQLの予約語を使用しない
- テーブル修飾子：テーブルを結合（JOIN）した場合は、どのテーブルのカラムか判別できるよう、カラム名にテーブル修飾子（エイリアス）を必ず付ける

### 4. 構文・関数・型のルール

- ソートとグループ化：`group by` と `order by` は、カラム名またはエイリアスで指定する（数字によるインデックス指定はNG）
- 絞り込み：`row_number` などのウィンドウ関数の結果に対する条件の絞り込みには、`qualify` 句を使用する
- 条件分岐：単一の条件評価の場合は `case` 文ではなく `if` 文で実装する
- 文字列操作：
  - 文字列結合は `concat()` ではなく `||` を使用する
  - 正規表現のパターンはRaw String（`"` や `'` の先頭に `r` をつける）で表現する
- 日付操作：
  - 日付の比較を行うときは、型を揃えてから比較する
  - 日付型への変換は `cast()` ではなく `date()` を使用する
  - 日付関数（`current_date`、`current_datetime` 等）を使用するときは、タイムゾーンを指定する

## 🟡 Want（推奨されるルール）

### 1. フォーマット・可読性向上

- 改行コード：LF にする
- セミコロン：文末のセミコロン（`;`）は単独の行に置く
- 括弧の改行：括弧内の条件句で改行する場合、閉じ括弧 `)` の位置は、開き括弧 `(` が含まれる文字列の先頭に合わせる
- IN句：`in` 句の中身はインデントして見やすくする
- JOINのON句：結合キーが2つ以上ある場合は改行する

### 2. クエリ構造・最適化

- サブクエリの扱い：サブクエリを使う際は原則として `with` 句を使用する。また、`with` 句内のサブクエリのネスト（深さ）は2段階までを目安とする
- 命名（英語表記）：カラム名や `with` 句の名前は、ローマ字読みではなく英語表記にする
- リネーム：カラム名やテーブル名の不必要なリネーム（意味の変わらない別名付与）は避ける
- 無駄な処理の排除：パフォーマンス低下を招く不要な処理は書かない
  - 例：類似した関数の二重記載を避ける
  - 例：分析に使用しない不要な列（`select *` 等）の取得を避ける
