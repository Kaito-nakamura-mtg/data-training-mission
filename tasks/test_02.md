## 使用するテーブル

BigQueryデータセット `advanced_sql_test` に、以下3テーブルがあります。

### `employees`（従業員マスタ）

| カラム名 | 型 | 説明 |
|---|---|---|
| employee_id | INT64 | 従業員ID |
| name | STRING | 氏名 |
| manager_id | INT64 | 上司の従業員ID（CEOはNULL） |
| department | STRING | 所属部署 |
| hire_date | DATE | 入社日 |
| salary | INT64 | 年収 |

### `categories`（商品カテゴリマスタ）

| カラム名 | 型 | 説明 |
|---|---|---|
| category_id | STRING | カテゴリID |
| category_name | STRING | カテゴリ名 |

### `sales_history`（売上履歴）

| カラム名 | 型 | 説明 |
|---|---|---|
| sale_id | STRING | 売上ID |
| sale_date | DATE | 売上日（2024年1月〜4月） |
| store_id | STRING | 店舗ID（S01, S02） |
| employee_id | INT64 | 担当従業員ID（**NULLの場合あり**：オンライン販売等で担当者不明） |
| customer_id | STRING | 顧客ID（**NULLの場合あり**：匿名購入） |
| category_id | STRING | カテゴリID |
| amount | INT64 | 売上金額（**NULLの場合あり**：返品等で金額未確定） |

> ⚠️ 実務データと同様、いくつかのカラムにNULLが混在しています。集計・比較を行う際は、NULLがどのように結果へ影響するかを必ず意識してください。

## 問題2

【テーマ】第4章 3値論理とNULL / 第22章 NULL撲滅委員会 / 第8章 外部結合の使い方

### 抽出要件

`categories`（マスタ）と `sales_history` を使い、**カテゴリごと**に以下を集計してください。ただし、一度も売上のないカテゴリも結果から漏らさないこと。

1. 総取引件数（amountがNULLの取引も含む件数）
2. 金額が確定している取引件数（amountがNULLでない件数）
3. 「金額が確定している取引のみ」を対象とした平均取引金額
4. 「金額未確定の取引を0円とみなした場合」の平均取引金額

3と4の結果を比較し、**なぜ差が生まれるのか**、そして「返品等で金額が未確定な取引」を業務上どちらの考え方で扱うべきかをコメントとして書いてください（正解は一つとは限りません。考え方を説明できることが重要です）。

## 問題5

【テーマ】第6章 HAVING句の力 / 第9章 SQLで集合演算 / 第11章 SQLを速くするぞ

### 抽出要件

1. **HAVING句**を使い、「2024年1月〜4月の4ヶ月間、毎月必ず売上を上げていた従業員」を抽出してください（`employee_id` がNULLの取引は集計対象から除外すること）。
2. **集合演算（`INTERSECT` / `EXCEPT`）**を使い、以下3グループの顧客IDをそれぞれ求めてください。
   - 継続顧客：2024年1月と2024年4月の両方に購入履歴がある顧客
   - 離脱顧客：2024年1月には購入履歴があるが、2024年4月には購入履歴がない顧客
   - 新規顧客：2024年4月には購入履歴があるが、2024年1月には購入履歴がない顧客
3. 2で書いたSQLについて、もし「顧客ごとに相関サブクエリで『1月に買ったか』『4月に買ったか』を個別に判定する」書き方をした場合と比べて、集合演算を使う書き方にはどのようなパフォーマンス上のメリットがあるか、考えを記述してください。

### 期待される出力結果のイメージ（1について）

| employee_id | active_months |
|---|---|
| (該当する従業員ID) | 4 |
| ... | ... |

### 期待される出力結果のイメージ（2について）

| customer_id | status |
|---|---|
| (顧客ID) | 継続 |
